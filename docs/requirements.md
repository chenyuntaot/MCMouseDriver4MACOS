# 需求分析

版本：v1.1 · 2026-08-08（v1.1：软件形态明确为 macOS 菜单栏应用，排除网页方案）

---

## 1. 背景与问题

迈从 A7 系列鼠标（瑞昱主控，PAW3395/PAW3950 传感器，三模，最高双 8K 回报率）
的官方配置软件 MCHOSE HUB 仅有 Windows 版。在 macOS 上，DPI 档位、回报率、
按键映射、宏、灯效等参数要么无法修改，要么只能用鼠标上最后一次保存的配置。

用户（本项目唯一用户）使用 macOS（Apple Silicon），需要一个本地可用的配置工具。

### 1.1 官方软件能力（逆向已知）

MCHOSE HUB = Electron 壳 + 远程 Web 应用（`www.mchose.com.cn`），配置通道为
USB HID 厂商自定义接口（浏览器端 WebHID / 桌面端 node-usb）。Web 端能力即协议
能力的全集，一期从中裁剪。详见 `kb/architecture/0001`。

### 1.2 目标

在 macOS 上实现官方驱动的核心配置能力：**基础设置、按键与宏、灯效与电量**
（用户在 2026-08-08 需求访谈中确认的三项）。软件形态为 **macOS 菜单栏应用**
（Python + hidapi，无 Dock 图标常驻菜单栏，不使用网页/WebView），
先 CLI 验证协议，二期出菜单栏 GUI。

## 2. 用户画像与使用场景

唯一用户：开发者本人，macOS 用户，有编程能力，能接受 CLI 作为一期形态。

典型场景：
- S1：换电脑/重装后，把 DPI、回报率调成习惯值。
- S2：把侧键映射为指定功能（如前进/后退/自定义键）。
- S3：录制并下发一个宏到板载存储。
- S4：查看电量，调整/关闭 RGB 灯效以省电。
- S5：把配置导出存档，之后一键恢复。

## 3. 功能需求

优先级：P0 必须有，P1 应该有，P2 可以后补。

### FR-1 设备发现与连接（P0）

- 枚举并识别 A7 鼠标本体（有线模式）与 2.4G 接收器两种 HID 通道，
  展示 VID/PID、固件版本、当前连接方式、当前 DPI/回报率概览。
- 蓝牙模式：仅识别并提示"蓝牙模式不支持配置"，不做配置（一期）。
- 设备未连接 / 被占用 / 权限不足时给出明确报错与指引。
- 验收：CLI `mcmouse info` 在有线与 2.4G 两种连接下均输出正确设备信息。

### FR-2 基础设置（P0）

- DPI：读取/设置各档位数值与当前档位；档位数、取值范围、步进以设备能力矩阵
  （kb/devices 档案）为准，不硬编码。
- 回报率：读取/设置 125/250/500/1000/2000/4000/8000 Hz 中设备支持的档位；
  8K 仅在对应接收器/有线模式下可选。
- 传感器辅助项（以官方 Web 端对 A7 实际开放的项为准，逐项登记知识库）：
  LOD 高度、直线修正（angle snapping）、波纹控制（motion sync/ripple）、
  防抖（debounce）、静默高度等。
- 恢复出厂设置（仅配置项，不含固件）。
- 验收：每项设置写入后重新读取一致；官方 Web 端（Windows/Chrome）读取到相同值。

### FR-3 按键映射与宏（P0）

- 读取/设置各按键（左/右/中/侧键/DPI 键，以实际键数为准）的映射：
  鼠标键、键盘键、多媒体键、DPI 切换、宏、禁用。
- 宏：创建（录制按键序列与延迟）、编辑、删除、绑定到按键；写入板载存储。
- 配置板载 profile（若设备支持多 profile，切换与保存）。
- 验收：映射/宏写入后在 macOS 系统层面生效；断电重连后保持（存于板载）。

### FR-4 灯效与电量（P1）

- 灯效：读取/设置模式（常亮/呼吸/循环/关闭等，以设备支持为准）、颜色、亮度、速度。
- 电量：读取电量百分比与充电状态；2.4G 模式下读取接收器侧的电量上报。
- 验收：灯效修改即时生效；电量读数与官方 App 一致（允许 ±1% 误差）。

### FR-5 菜单栏形态（P1）

- 无 Dock 图标，常驻系统菜单栏，支持开机自启（可开关）。
- 菜单栏菜单内展示：连接状态、当前 DPI 档位与回报率、电量（S4 场景一眼可见）。
- 菜单内快捷操作：切换 DPI 档位/profile、开关灯效、打开设置面板、退出。
- 设置面板从菜单栏唤出，承载 FR-2~FR-4 的完整配置 UI；关闭面板不退出应用。
- 验收：日常操作全程无需打开终端；面板关闭后快捷操作仍可用。

### FR-6 配置持久化与迁移（P1）

- 本地保存多份命名配置，支持应用、导出、导入。
- 导入时对非法取值做校验并拒绝，防止写入坏配置。
- ⚠ 与官方配置格式互通：待官方格式逆向后决定（二期候选）。

### FR-7 固件升级（明确不做，二期）

一期禁止任何固件读写路径（见 `AGENTS.md` 安全红线）。二期再评估 OTA 协议
（官方 IPC 中存在 `otaDevice`、`getFirmwareBinData` 等入口，可作为二期线索）。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 平台 | macOS 14+（Apple Silicon 优先），无需 root、无需关闭 SIP |
| 权限 | 尽量零权限申请；如 macOS 强制要求"输入监控"，需在给用户的报错里说明 |
| 可靠性 | 所有写操作先读现状、失败可回滚；非法取值本地拦截，不发给设备 |
| 可测试性 | 协议层 100% 可用录制报文离线测试；真机测试单独标记 |
| 可维护性 | 协议结论全部登记知识库；代码只引用知识库结论（AGENTS.md 规则） |
| 性能 | 单次设置读写 < 500ms；常驻内存 < 100MB（GUI 期） |
| 合规 | 不分发官方素材；仅个人学习用途 |

## 5. 范围边界

做：macOS 上的 A7 系列配置（有线 + 2.4G）。
不做（一期）：固件 OTA；蓝牙模式配置；Windows/Linux；其他迈从设备
（键盘/耳机等，架构允许后续按设备档案扩展）；云同步/账号体系。

## 6. 里程碑与验收

| 里程碑 | 交付 | 验收标准 |
|---|---|---|
| M0 逆向与立项 | 解包产物、知识库初始化、本文档与选型方案 | 知识库含官方架构条目；文档齐全 |
| M1 协议库 + CLI | `mcmouse.protocol` + `mcmouse` CLI | FR-1/2/3 在真机（有线+2.4G）验证通过；协议层单测全绿 |
| M2 菜单栏应用 | PySide6 accessory 模式 GUI，覆盖 FR-1~FR-6 | 非技术用户可按 README 完成 S1~S5 场景；全程无 Dock 图标 |
| M3 打包 | 签名/公证的 .app（或 brew 安装） | 干净 macOS 机器上双击可用 |

## 7. 风险登记（需求视角）

- R1 协议未完全逆向 → 部分 FR 缩水：按"已 verified 才进 GUI"的原则裁剪，不硬上。
- R2 官方固件升级改变协议 → 知识库记录固件版本，设备档案标注适用固件范围。
- R3 写配置导致设备异常 → 恢复出厂命令（FR-2）作为兜底，CLI 一期就提供。
- R4 macOS 权限收紧 → 选型文档 §5 已列 fallback 路线。
